# 部署指南

目标：拿到一个公网网址，手机和电脑都能打开。

这个站点是**纯静态**的（只有 HTML/CSS/JS/字体，没有后端、没有构建步骤），
但有**两个必须同时满足**的条件，缺一不可：

| 条件 | 说明 |
| --- | --- |
| **A. 托管平台的域名国内能打开** | 否则网页本身就打不开 |
| **B. 网页能取到 bgm.tv 的数据和海报** | bgm.tv 国内被墙，直连必然失败 |

**A 和 B 是两个独立的问题。** 网页托管在哪个平台，和它能不能访问被墙的 bgm.tv，是两件事。
好消息是 B 有干净的解法（中转服务），不受 A 影响。

---

## 一、先说清楚现状（实测数据）

我在你的网络环境下实测了直连与代理两条路径：

| 目标 | 直连 | 走代理 |
| --- | --- | --- |
| `api.bgm.tv`（搜番、取条目） | ❌ 超时 15 秒 | ✅ 200 / 0.57 秒 |
| `lain.bgm.tv`（海报图） | ❌ 超时 15 秒 | ✅ 200 / 0.51 秒 |
| `www.baidu.com` | ✅ 0.41 秒 | — |

而且 DNS 也被污染了：在你本机 `lain.bgm.tv` 被解析到 `31.13.112.9`，那是 Facebook 的 IP 段。

**结论：在国内，只有三种办法能取到 bgm.tv 的数据。**

1. **设备上开着代理**（你现在电脑就是这样，所以一直能用）
2. **配一个中转服务**（推荐，见第三节）
3. **不用 bgm.tv**，改成自己上传海报图 + 手动填写标题评分（工具已支持，无需任何网络）

## 二、托管平台选择（条件 A）

**欧美系平台（Vercel / Netlify / Cloudflare Pages / GitHub Pages）的默认域名在国内都不稳定。**

- Vercel 官方知识库自己承认：站点在中国大陆 "may load slowly or fail to load"
  （<https://vercel.com/kb/guide/accessing-vercel-hosted-sites-from-mainland-china>）
- Cloudflare Pages 的节点分布被中文社区形容为"环大陆"，国内体验不佳，通常需要自建优选域名
- Gitee Pages **已于 2024 年 5 月下线**，不要再考虑

### 推荐：腾讯云 EdgeOne Pages（免备案）

这是目前唯一能同时满足「国内可访问 + 免备案 + 不用命令行」的免费方案。

1. 打开腾讯云 <https://cloud.tencent.com/> 注册并完成**实名认证**（必须）
2. 进入 **EdgeOne Pages** 控制台
3. 选择**直接上传**（拖拽整个文件夹），把本项目文件夹（不含 `tools/`、`.git/`）拖进去
4. 等几十秒，会得到一个 `*.edgeone.app` 之类的网址，直接就能分享

> 注意：**不使用大陆加速节点时**，EdgeOne 会分配一个走海外节点的二级域名，**不需要备案**。
> 如果你要用自己的域名并开启大陆加速，那就**必须完成 ICP 备案**。

### 备选

| 平台 | 国内访问 | 需要备案 | 操作方式 |
| --- | --- | --- | --- |
| Cloudflare Pages | ⚠️ 时通时断 | 免 | 拖拽上传，或连 GitHub |
| Vercel | ⚠️ 慢/常失败 | 免 | 拖拽上传，或连 GitHub |
| Netlify | ⚠️ 较差 | 免 | <https://app.netlify.com/drop> 直接拖文件夹 |
| GitHub Pages | ⚠️ 波动大 | 免 | 推仓库后开 Pages（本项目已含 `.nojekyll`） |
| 阿里云 OSS / 腾讯云 COS | ✅ 很快 | **必须备案** | 上传后开静态网站 |

本项目已经放好了这些平台的配置文件：`vercel.json`、`netlify.toml`、`.nojekyll`，
所以上面任何一个平台都是「上传即可」，不需要填构建命令（本项目没有构建步骤）。

## 三、中转服务（条件 B，推荐做法）

思路：把一个小程序部署到**墙外**的平台，由它去取 bgm.tv 的数据，
你的浏览器只跟这个程序说话，于是绕开了墙。

### 用 Cloudflare Workers（免费，约 3 分钟）

1. 打开 <https://dash.cloudflare.com/> 注册 / 登录（免费）
2. 左侧 **Compute (Workers)** → **Create** → 选 **Start with Hello World!**
3. 名字随便起，比如 `bgm-relay`，点 **Deploy**
4. 点 **Edit code**，把本项目 `relay/cloudflare-worker.js` 的**全部内容**粘进去覆盖
5. 点 **Deploy**
6. 复制得到的地址，形如 `https://bgm-relay.你的用户名.workers.dev/`
7. 回到工具 → 「**网络中转**」→ 把地址粘进去 → 点「**测试连接**」

看到「中转可用」就可以正常搜番取图了。这个地址会记住，下次打开自动生效。

> **关于地址被滥用**：Worker 里已经加了域名白名单，只允许 `bgm.tv` 相关域名，
> 别人拿到地址也没法把它当公开代理用。
> 想再加一层保险，可以在 Worker 的设置里加环境变量 `RELAY_TOKEN=你的口令`，
> 然后中转地址填成 `https://xxx.workers.dev/?token=你的口令`。

### 已经开着代理的话

如果你的手机和电脑都一直开着代理，那么**不用配中转**，直连就能用。
工具的逻辑是**直连优先、失败才走中转**，所以配了中转也不会有额外损失，
只是在能直连时会省一次跳转。

### 自己搭中转

`relay/dev-relay.mjs` 是同一套逻辑的 Node 版，可以部署到任何支持 Node 的地方
（Zeabur、Railway、自己的服务器等）：

```bash
node relay/dev-relay.mjs 8787
```

它同样只允许 bgm.tv 相关域名，且 CORS 头已配好。注意它需要**能被公网访问**，
部署到国内服务器时需要备案域名；部署到墙外平台则不需要。

## 四、部署后务必做的验收

**不要只看电脑。** 用手机在**移动 / 联通 / 电信**网络下各测一次（至少测一个非你家 WiFi 的网络）：

1. ☐ 网址能打开（说明条件 A 满足）
2. ☐ 搜一部番能出结果（说明中转或代理生效，条件 B 满足）
3. ☐ 点结果能出海报、能点「下载 PNG」
4. ☐ 下载的图能存进相册
5. ☐ 微信里打开试试（未备案域名可能弹提示，这属正常现象）

有任何一步不通，对照第一张表就能定位是 A 还是 B 的问题。

## 五、几点已知限制

- **海报清晰度**：图源是 `/r/800/`（长边不超过 800px）。画布放大到 1080 宽时海报会被轻微放大。
  想要更清晰就直接用「上传自己的图片」，效果一样。
- **首次搜索可能要等几秒**：直连会先试 4.5 秒再回落中转。如果你确定要用中转，
  可以接受固定延迟，也可以在 `js/bgm.js` 里把 `directTimeout` 调小（比如 1500）。
- **微信内置浏览器**对未备案域名可能弹拦截提示；腾讯云社区有"已备案域名因同步延迟仍被提示"的反馈。
- **小红书 App 内打开第三方链接**通常受限，建议让读者复制到系统浏览器打开。
- 本工具**不存储任何数据**，没有后端，图片和文字全部在你的浏览器里生成。
